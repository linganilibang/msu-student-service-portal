# Development Process Evidence

1. **Case study analysis** — Reviewed the supplied HTML/CSS/JavaScript to identify the portal's purpose: a single point of access for student-facing services.
2. **Problem identification** — Student information is spread across service pages; users need a quick way to find health, academic, finance, admissions and campus-life guidance.
3. **Planning** — Defined the one-page information architecture, service cards, quick links, directory, campus visual and enquiry form.
4. **Interface design** — Established a navy/teal/gold palette, card-based layout, readable typography, visible focus states and responsive breakpoints. See `wireframe.svg`.
5. **HTML5 development** — Semantic header, navigation, main, sections, aside, form labels, buttons and footer.
6. **CSS3 / responsive design** — Grid and flex layouts, design tokens, mobile breakpoints, hover/focus states and reduced-motion support.
7. **JavaScript interactivity** — Service search/filter, expandable details, directory jumps, mobile menu, email-draft form and modal demo.
8. **Multimedia / p5.js integration** — Original local SVG campus banner and p5.js interactive network visual linking six service nodes to matching service cards.
9. **Testing** — A repeatable test plan is supplied in `tests/test-plan.md`. Mark each case Pass/Fail after running it in the target browser; do not present prepared cases as completed tests.
10. **Documentation** — This process record, README, and project report document structure, purpose and limitations.
11. **Final demonstration** — Open `index.html`, demonstrate search/filter and details, select a campus-network node, prepare an enquiry, resize the viewport, and show the demo login with an explicit explanation that it is not real authentication.
